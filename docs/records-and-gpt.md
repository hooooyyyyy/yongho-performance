# 캘린더 회고와 주간 리포트 사용법

## 현재 가능한 일

로그인 없이 기존 기기 저장을 계속 사용한다. 운동 완료 전에 세트 입력·운동 메모·컨디션·일지를 저장하고, 완료한 날짜의 캘린더 회고로 이동한다. 자정이 지나도 운동을 시작한 날짜가 유지된다. 완료 버튼 중복 입력은 막고 완료 시각을 다시 생성하지 않는다. 기록 수정은 기준 루틴과 분리된다.

기록 → 캘린더에서 날짜를 누르면 운동 이름·세트·시간·컨디션·운동별 느낌을 본다. 긴 원문과 수정 이력은 펼쳐 본다. 진행 중/일지 기록은 완료 출석과 구분된다. 여러 세션이 있으면 세션별로 본다. 이날 기록 수정으로 원래 날짜 세션을 다시 연다.

기록 → 주간 리포트에서 해당 주를 선택한다. 본세트는 반복수/중량이 비어 있어도 기록된 세트로 센다. 웜업·드롭·테스트를 별도로 센다. 최근 4주의 주요 목표 부위별 본세트를 제공하며 보조근을 임의 환산하지 않는다. 수면은 기록된 날짜 수를 표시하고, 시간 평균에는 직접/추정 기록 포함 개수를 표시한다. 0/미기록을 실제 운동하지 않음이나 RIR 0으로 해석하지 않는다.

## GPT와 주간 분석을 주고받기

일반 GPT 대화창은 앱의 IndexedDB를 직접 읽거나 쓰지 못한다. 계정 기록 조회용 MCP 서버와 승인 화면은 추가했으며, 실제 배포·OAuth 설정·ChatGPT 연결 순서는 [gpt-connection.md](gpt-connection.md)를 따른다. 연결 전에는 아래 파일 방식이나 계정 화면의 전체 기록 복사를 사용한다. 브라우저에 WebMCP 도구를 등록했다는 사실만으로 일반 ChatGPT나 아이폰에서 도구를 사용할 수 있다고 보장하지 않는다. 앱 안의 로컬 규칙과 GPT 분석을 구분한다.

1. 주간 리포트 → **GPT에 줄 기록 내려받기**. 선택 주와 직전 4주 원본·메모·원문·기준 루틴·부위 분류·이전 주 리포트를 포함한 비공개 JSON이다.
2. GPT 대화에 파일을 첨부하고 “이 기록으로 주간 분석하고, 앱에 가져올 리포트 JSON도 만들어줘”라고 요청한다. 파일의 instructions에 반환 양식이 있다.
3. GPT가 만든 JSON을 **GPT 리포트 가져오기**로 선택한다. 같은 기기에서 내려받은 contextId를 사용해야 한다. 다른 기기로 옮길 때는 전체 백업도 복원해야 한다.
4. 결과가 정상 저장되면 자동으로 아카이브에 들어간다. 재분석은 새 requestId로 v2 등을 만든다. 같은 요청 ID의 재시도는 같은 버전을 반환하고, 같은 ID의 다른 결과는 거부한다.
5. 원본이 바뀌면 이전 기록 기준이라는 표시가 뜬다. 과거 리포트의 분석 근거 파일은 그대로 내려받을 수 있다.

**현재 로컬 요약 보관**은 숫자 집계와 기록 보완 안내다. GPT의 성장·정체·회복 판단을 대신하지 않는다. 정기 자동 생성이나 별도 OpenAI 호출은 없다.

리포트 결론에는 잘한 점·제약·주요 변화·다음 행동 최대 3개와 확인 기준을 둔다. 상세에는 운동별 추세·최근 훈련 분배·피로·회복·관찰 근거·미확인 사항·확신도·자연어 설명을 둔다. 다음 주 분석은 과거 제안을 읽고 기록에서 확인되는 실행/미실행/미확인을 구분한다. 운동 메모의 가동범위·속도 변화와 숫자를 함께 검토하며, 타는 느낌만으로 성장/좋은 자세를 단정하지 않는다.

## 원문과 리포트 보존

IndexedDB v5는 v3/v4의 기존 세션·세트·meta를 삭제하지 않고 reports 저장소만 추가한다. 일지 수정 시 기존 문자열 journal을 유지하면서 journalEntries에 원문 버전을 보존한다. 기존 원문은 최초 수정 때 legacy 항목으로 함께 보존한다. 기록이 바뀌지 않은 저장은 revision을 갱신하지 않는다.

리포트는 id, requestId, contextId, 주 시작/끝, 한국 시간대, 로컬 버전 번호, 생성 시점, 기록 조회 시점, 진행/마감 상태, 분석 종류, 구조화된 결과, sourceRevisions, sourceSnapshot을 가진다. sourceSnapshot에는 선택 주와 직전 4주 원본 사본을 넣는다. 보관 후 내용을 덮어쓰지 않는다.

백업 v3는 sessions/sets와 reports·원문 이력·충돌 사본·분석 입력 묶음을 포함한다. v1/v2도 읽는다. 로컬/원격 ID 충돌은 양쪽을 보존하며 자동 승자를 고르지 않는다. 복원 시 새 기록의 원본 revision을 유지하므로 기존 리포트의 근거와 연결된다. 계정 토큰과 동기화 계정 바인딩은 백업에 포함하지 않는다.

## 다음 단계: GPT 채팅 → 자동 기록 → 자동 조회

앱 입력 대신 GPT 대화로 하루 운동을 남기려면 인증된 비공개 공용 저장소와 원격 도구가 필요하다. 로그인은 이 연결과 본인 기록 접근 확인에 쓰며, 로컬 사용의 필수 절차는 아니다.

| 서버 도구 | 입력/처리 |
| --- | --- |
| read_workout_history | 인증된 본인 날짜 범위·세션·세트·원문·메모 읽기 |
| record_workout_experience | requestId, 날짜/루틴, 원문 전체, 구조화된 세트·컨디션·운동 메모·시간. 불확실한 값 null. 요청 재시도 중복 방지. 세션·세트·원문을 하나의 DB 트랜잭션으로 저장 |
| prepare_weekly_report | 선택 주와 최근 4~8주, 이전 제안, 소유자·원본 revision 검증 후 입력 스냅샷 발급 |
| save_weekly_report | contextId/requestId, 구조화 결과와 자연어. 원본 조회 당시의 근거에 연결하여 새 버전 저장 |

서버는 GPT에서 임의 userId를 받아 신뢰하지 않고 인증 토큰에서 사용자 ID를 얻는다. 인증·도구 연결 방법은 실제 ChatGPT 환경에서 확인한 뒤 붙인다. browser anon key만으로 GPT에 개인 기록 접근을 허용하지 않는다. 쓰기 전 기존 날짜·루틴의 중복/수정 내용을 보여주고, 기존 내용의 변경은 명시적으로 검토한다. 원문과 숫자를 다른 세션에 흩어 저장하지 않는다. 성공 응답은 DB 저장 완료 후 기록 ID를 포함하며 연결 실패 시 저장됐다고 답하지 않는다.

현재 Supabase 어댑터/미리보기/충돌 엔진/SQL은 준비됐으나 인증 UI·자동 동기화·원격 도구 서버는 연결하지 않았다. 브라우저 WebMCP의 기존 세트 추가 도구는 append 방식이므로 중단 뒤 재시도 전 조회가 필요하다. 실제 연결 때는 위 원자적/중복 방지 서버 도구를 우선한다. 여러 기기가 오프라인에서 같은 주 리포트를 동시에 만들 경우 UUID 사본은 모두 보존하고, 표시 버전은 연결 때 계정 단위 순번으로 확정해야 한다.

Supabase 프로젝트 URL과 공개 publishable/anon key가 연결 단계에 필요하다. service-role/OpenAI 비밀키를 공개 저장소나 브라우저 코드에 넣지 않는다. GPT가 분석하는 경로에는 별도 OpenAI API 키가 필요하지 않다. 앱 자체 AI 기능을 추가할 때만 별도 서버 API 경로를 사용한다.

분석 → 제안 → 사용자 확인 → 별도 루틴 변경만 허용한다. 현재 아카이브 저장 도구에는 루틴 변경 권한이 없다.

## iPhone 확인

업데이트 후 기존 날짜의 세트·빈 반복수·일지가 유지되는지 확인한다. 새 테스트 세션 완료 직전 입력을 수정해 캘린더에 반영되는지, 앱을 다시 열어 아카이브와 원문이 남는지, 전체 백업 다운로드/복원이 되는지 확인한다. 개발 환경에서 실제 아이폰 IndexedDB는 볼 수 없다.

## 연결 단계 현황

앱 로그인·검토 후 병합·오프라인 우선 동기화를 구현했다. 실제 보관함 SQL과 인증 URL은 `cloud-setup.md`를 따른다. 일반 GPT 대화의 직접 기록 도구는 아직 별도 연결이 필요하다.
